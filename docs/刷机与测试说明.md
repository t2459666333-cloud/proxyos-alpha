# ProxyOS Alpha 0.2.0 刷机与测试说明

## 当前设备

当前设备上的 0.1.1 热修复可继续使用；多格式订阅、备用节点、无线详细设置和备份恢复需要刷入 0.2.0。浏览器若仍显示旧界面，请按 `Ctrl+F5` 强制刷新。

- 管理地址：`http://192.168.10.1`
- 用户名：`root`
- 初始密码：空
- 默认 LAN：`192.168.10.1/24`
- 默认网口：第一个物理口为 WAN，其余物理口为 LAN

首次登录后请尽快通过 SSH 执行 `passwd` 设置管理员密码。

## 制作启动 U 盘

1. 备份 U 盘原有数据。
2. 使用 Rufus 或 balenaEtcher 选择对应的 `.img.gz`。
3. 新式设备优先使用 UEFI 镜像；旧设备使用 BIOS 镜像。
4. 写入目标必须是测试 U 盘，不能选电脑系统盘。
5. 在 BIOS/UEFI 启动菜单中选择该 U 盘。

## 首轮测试顺序

1. 先只连接一个 LAN 口，确认电脑获得 `192.168.10.x`。
2. 打开 `http://192.168.10.1`，检查四个核心页面的布局。
3. 在“网络”页核对网口、驱动、速率和 WAN/LAN 角色。
4. 确认 WAN 获得上级地址并能访问互联网。
5. 在“Wi-Fi”页检查硬件状态。没有 AP 能力时应明确显示不可用。
6. 在“节点”页添加已知可用的 sing-box outbound JSON。
7. 测试节点并在“设备”页为终端指定该节点。
8. 用终端查询公网 IP，确认设备使用了选定出口。
9. 分别测试系统默认、直连、指定节点和禁止联网。
10. 重启系统，确认节点、设备策略和网口角色仍然保留。

## 网口配置回滚

修改网口角色后系统等待 90 秒确认。如果新配置导致管理页面失联，不要继续操作，系统会自动恢复原来的 `/etc/config/network`。

## 已知限制

- Clash 订阅只导入代理节点，不导入 Clash 规则、策略组和 rule-provider。
- 自动选择和主备切换以最近一次健康检测结果为准，后台每 5 分钟刷新一次。
- Wi-Fi AP 能力取决于无线芯片、固件和驱动；没有兼容无线网卡时页面只提供检测结果。
- LAN IPv6 默认关闭，用于避免 Alpha 测试阶段发生 IPv6 绕过。
- 当前设备的上级网关 `192.168.1.1` 尚不能正常访问公网时，订阅、节点测速与出口检测都会失败，需要先恢复上级网络。
